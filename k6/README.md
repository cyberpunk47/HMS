# HMS k6 Benchmark Suite

## Layout
```
k6/
  prepare.js       <- creates benchmark users and writes fresh tokens.json
  tokens.json      <- generated by prepare.js; do not hardcode JWTs
  config.js        <- phase presets, target rate math, traffic mix weights
  helpers.js        <- token pool (SharedArray), tagged request wrappers
  payloads.js       <- DTO-shaped request bodies
  benchmark.js      <- main script, run this
```

## Run order — do not skip validation

```bash
# 0. Fresh DB / fresh EC2 setup. Creates users if missing, logs in, and writes k6/tokens.json.
BASE_URL=http://localhost:9000 PATIENT_COUNT=1000 DOCTOR_COUNT=1000 node prepare.js

# 1. Validation (1,000 requests / 60s, ~16.67 req/s) — catches wrong field
#    names, wrong URLs, CORS/auth issues cheaply, on your own machine.
k6 run -e BASE_URL=http://localhost:9000 -e PHASE=validation benchmark.js

# Check the JSON summary printed to stdout:
#   - dropped_iterations should be 0
#   - error_rate should be near 0
#   - if errors_post / errors_put counters are non-zero, inspect the endpoint
#     tags in summary-validation.json before continuing

# 2. Tier 1 — 100,000 requests / 600s (~166.67 req/s)
k6 run -e BASE_URL=<your-url> -e PHASE=100k benchmark.js

# 3. Tier 2 — 500,000 requests / 600s (~833.33 req/s)
k6 run -e BASE_URL=<your-url> -e PHASE=500k benchmark.js

# 4. Tier 3 — 1,000,000 requests / 600s (~1,666.67 req/s)
k6 run -e BASE_URL=<your-url> -e PHASE=1m benchmark.js
```

Swap `BASE_URL` only between local / EC2-Docker / k3s-ingress runs — nothing
else in the script changes.

## Before trusting any number from a run

1. **`dropped_iterations` must be 0.** If it's not, k6 couldn't sustain the
   requested rate — report the actual `achieved_rate_rps` from the summary,
   not the phase's target number.
2. **Check `errors_get` / `errors_post` / `errors_put` / `errors_login` /
   `errors_signup` individually** — a single dominant error source tells you
   exactly which endpoint tag to inspect in `summary-<phase>.json`.
3. **Reseed/reset the DB between the 100k/500k/1m tiers** if you're running
   them back to back — otherwise growing table sizes from earlier tiers'
   writes will quietly skew the comparison between tiers.
4. Each run also writes `summary-<phase>.json` next to the script with the
   full raw k6 metrics (every tag, every percentile) for later comparison.
